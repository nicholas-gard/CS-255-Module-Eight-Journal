# CS-255-Module-Eight-Journal
CS 255 Module Eight Journal Submission

The client for the DriverPass system was Liam the owner of the company. The type of system I wanted to design was an efficient tool to help customers with driving lessons. Particularly I wanted prospective drivers to be able to study for the exam, schedule lessons and get feedback from their instructors. Of these parts I think I designed the lesson scheduling the best. It is a streamlined process that ensures drivers don't get overbooked but the student still gets their preferred time. 

If I could revise anything it would be administration side. I think I was missing describing  their account controls such as deleting and banning users. I would improve it by adding more methods describing account management and specify that they are responsible for updating the apps security.

I incorparated the users needs whenever possible in my design. Specifically I made it possible for them to send tickets to administrators and the ability to schedule lessons online. It is very important to consider the user experiance on top of the companies requests because users are the reason the app exists. A bad user experiance can destroy even the most essential of applications and a lack of users is always bad business. 

I approach designing a system by sectioning it off into objects and elaborating from there. I find the object oriented design to be the most understandable and almost all software can be simplified into objects and relationships. I plan to use some form of object diagram in all my software development as it gives structure to my thoughts and can easily be translated into code.
